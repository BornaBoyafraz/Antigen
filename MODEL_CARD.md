# Antigen model card

## Model summary

Antigen is a local, interpretable binary classifier that estimates whether a
block of text is benign or contains a prompt-injection attempt. It is designed
for text that may be placed into a language model's context, including direct
user messages and third-party content such as webpages, emails, documents, and
tool results.

The model returns a `benign` or `injection` label, an injection score, and a
human-readable explanation of the signals that contributed to the decision.
The default decision threshold is 0.5.

## Intended use

Antigen is intended for:

- local experimentation with prompt-injection detection;
- pre-screening user-supplied or retrieved text before it enters a model
  context;
- prioritizing suspicious content for human review;
- demonstrating an interpretable classifier and an evaluation methodology for
  direct and indirect prompt injection.

The score should be one input to a broader defense-in-depth system. A real
deployment should combine it with source provenance, tool permissions,
least-privilege execution, output validation, rate limits, logging, and human
review appropriate to the risk.

## Out-of-scope use

Antigen is not intended to:

- serve as the sole security boundary for autonomous or privileged actions;
- certify that text is safe merely because it receives a benign label;
- detect malicious code, malware, phishing, factual errors, or harmful content
  that does not attempt to steer a model;
- identify the author, intent, or trustworthiness of the text's source;
- provide general multi-turn conversation safety analysis. The separate
  conversation scorer detects only explicit codeword-smuggling setups;
- support claims of production readiness or state-of-the-art performance.

## Training data

`data/generate_dataset.py` produces the entire labeled corpus in
`data/prompts.jsonl`. At the time of this card, the generated dataset contains
322 rows: 164 benign and 158 injection examples. The category counts are:

| Category | Rows |
|---|---:|
| `benign` | 64 |
| `benign_hard` | 38 |
| `benign_wrapped` | 62 |
| `direct_injection` | 51 |
| `indirect_injection` | 56 |
| `jailbreak_roleplay` | 15 |
| `obfuscated_base64` | 18 |
| `obfuscated_hex` | 6 |
| `obfuscated_zero_width` | 12 |

The data is original and synthetic. It combines hand-written seed examples
with deterministic template combinatorics across direct injection, indirect
injection carriers, jailbreak framing, obfuscation, ordinary benign requests,
benign wrapped content, and difficult benign examples that quote or discuss
attack phrases. It is not scraped from a live system, a public benchmark, or
user conversations.

The evaluation harness uses a label-stratified 75/25 split with a fixed random
seed, yielding 241 training rows and 81 held-out rows. Because related
template-generated examples can appear on both sides of this split, it is not
a fully independent generalization test. A separate 30-row, hand-written
adversarial suite generated by `eval/build_adversarial_suite.py` shares no
generation templates with the training corpus and provides the harder check.

## Architecture

The primary scoring pipeline is a scikit-learn `FeatureUnion` containing:

1. character 3-to-5-gram TF-IDF features, using `char_wb` boundaries and a
   4,000-feature cap; and
2. engineered structural features for instruction overrides, role spoofing,
   text addressed to an assistant, indirect-content framing, encoded or
   obfuscated spans, imperative density, casing, and quote/discussion context.

The combined features feed a class-balanced logistic regression wrapped in
three-fold sigmoid calibration. At prediction time, a narrow deterministic
rule caps the score at 0.35 when every trigger match is quoted or discussed
and there is no indirect-content frame. This reduces a known false-positive
class without allowing quoted instructions inside fetched content to bypass
the classifier.

Explanations use the matched engineered signals plus positive character
n-gram contributions from a separate, uncalibrated logistic regression fitted
on the same feature union. The explanation model supports inspection; the
calibrated pipeline remains the source of the returned score.

## Evaluation

The following results come from running
`.venv/bin/python -m eval.harness` at the default 0.5 threshold. The held-out
split contains 41 benign and 40 injection examples. The adversarial suite
contains 10 benign and 20 injection examples.

| Evaluation set | Class | Precision | Recall | F1 |
|---|---|---:|---:|---:|
| Held-out split | Benign | 0.974 | 0.902 | 0.937 |
| Held-out split | Injection | 0.907 | 0.975 | 0.940 |
| Adversarial suite | Benign | 1.000 | 0.900 | 0.947 |
| Adversarial suite | Injection | 0.952 | 1.000 | 0.976 |

| Evaluation set | Accuracy | ROC AUC | Confusion matrix `[[TN, FP], [FN, TP]]` |
|---|---:|---:|---|
| Held-out split | 0.938 | 0.962 | `[[37, 4], [1, 39]]` |
| Adversarial suite | 0.967 | 0.990 | `[[9, 1], [0, 20]]` |

The regex-only baseline comparison measures whether the learned model improves
on a transparent keyword-and-pattern detector:

| Evaluation set | Model accuracy | Regex baseline accuracy | Absolute lift |
|---|---:|---:|---:|
| Held-out split | 0.938 | 0.568 | +0.370 |
| Adversarial suite | 0.967 | 0.300 | +0.667 |

The held-out split is small and still shares generator structure with the
training data. The adversarial suite is generator-disjoint but was authored
within the same project and is also small. These figures characterize the
checked-in test sets; they are not evidence of performance on the full
diversity of real-world attacks.

## Known limitations and failure modes

- **Quoted or discussed attacks remain the clearest false-positive class.**
  Benign security lessons, incident reports, detector tests, and research text
  can contain the same surface phrases as a live attack. At the measured
  operating point, `benign_hard` accuracy is 0.692 on the held-out split and
  0.750 on the adversarial suite. The discussion-context feature and score cap
  reduce this error mode but do not solve it.
- **The dataset is small and synthetic.** It cannot represent the vocabulary,
  languages, domains, formatting, or adaptive behavior found in production
  traffic.
- **Template overlap makes the held-out result optimistic.** The adversarial
  suite reduces this concern but is only 30 examples and is not a substitute
  for a large, independently collected benchmark.
- **Adaptive attackers can probe and evade fixed signals.** Character
  obfuscation, multilingual attacks, novel encodings, long-context dilution,
  and instructions expressed without familiar attack language may reduce
  recall.
- **Source context is absent.** The classifier scores text only. It does not
  know whether a string came directly from a user, a trusted internal system,
  or an untrusted webpage, even though that provenance can materially change
  risk.
- **Calibration is dataset-specific.** The returned score should not be read as
  a universal probability of attack under a different traffic distribution.
- **Multi-turn coverage is deliberately narrow.** Explicit codeword smuggling
  is handled by a separate scorer, while gradual or implicit escalation across
  turns is not.
- **English dominates the data.** Performance on other languages has not been
  established.

## Ethical and security considerations

False positives can block legitimate work, especially security research and
incident response; false negatives can expose downstream systems to hostile
instructions. Deployers should choose a threshold based on the cost of each
error, provide an appeal or review path for consequential decisions, and
measure performance on representative local traffic before enforcement.

Inputs may contain private emails, documents, credentials, or other sensitive
material. Although Antigen runs locally and makes no network calls, callers
remain responsible for access control, retention, redaction, and secure
logging. Explanations can reveal which patterns the detector recognizes, so
exposing detailed rationales to untrusted users may make evasion easier.

The classifier should not be used to infer personal traits or to penalize
people for discussing security topics. Dataset expansion and error analysis
should preserve provenance, consent, and privacy, and should report subgroup
or language gaps rather than assuming aggregate accuracy transfers equally.

## Reproducibility

Regenerate the corpus and adversarial suite, then run the evaluation:

```bash
.venv/bin/python data/generate_dataset.py
.venv/bin/python eval/build_adversarial_suite.py
.venv/bin/python -m eval.harness
```

The generation and split seeds are fixed. Dependency versions are constrained
by `pyproject.toml`; exact results can still vary if numerical library versions
or solver behavior change.
