01 / The problem

Untrusted text can become trusted instruction.

Direct injection is visible: a user tells an agent to ignore its rules. Indirect injection hides the same kind of instruction in a webpage, email, document, or tool result that an agent retrieves on someone’s behalf.

Different delivery route, same security question: is this text trying to steer the assistant in a way the legitimate user did not ask for?

Direct

A hostile instruction arrives through the user-input channel.

Indirect

A hostile instruction rides inside content the agent fetches or reads.

02 / How it works

Two kinds of evidence. One inspectable decision.

Hand-engineered security signals and learned text patterns meet in a deliberately linear model. Every result includes the evidence that drove it.

01

Recognize known attack shapes

Independent regex and structural detectors surface override phrases, fake role markers, assistant-directed text, indirect frames, and encoding signals.

02

Generalize beyond keywords

Character 3–5-grams remain useful through spacing, punctuation, small misspellings, and wording the pattern bank does not explicitly contain.

03

Explain the outcome

A calibrated linear classifier returns the operating score; a separate linear explainer exposes real model inputs and learned contributions.

      05 / Honest limitations

      A useful detector should explain where it breaks.

      Antigen is a portfolio prototype and one layer in a defense-in-depth system. It does not certify that content is safe.

      01

      Small, synthetic dataset

      The checked-in corpus has 322 rows: 164 benign and 158 injection examples. It cannot capture production vocabulary, languages, domains, formatting, or adaptive behavior.

      02

      Quoted attacks remain difficult

      Benign security text can quote the same phrases as a live attack. Measured benign_hard accuracy is 0.692 held-out and 0.750 adversarial; the discussion-context cap reduces this error, but does not solve it.

      03

      Narrow multi-turn coverage

      The conversation scorer catches explicit codeword setup and later invocation. It does not model gradual, implicit, no-codeword trust escalation across turns.

      Deployment stance: combine the score with provenance, least-privilege tool permissions, output validation, logging, and human review. Calibration is specific to the checked-in data distribution.
